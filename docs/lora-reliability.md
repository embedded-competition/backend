# LoRa 신뢰성 모델 — 서버 설계 근거

프레임 사양은 [lora-frame.md](lora-frame.md)에 있다. 이 문서는 **왜 그렇게 정했는지**를
남긴다. 노드 구현에는 필요 없다.

## 연결을 두지 않는다

LoRa는 반이중 공유 매체다. TCP의 어떤 것을 쓰고 어떤 것을 버리는지 못 박는다.

| TCP 요소 | 채택 | 근거 |
|---|---|---|
| 체크섬 | **쓴다** (CRC-16) | 텍스트 파싱 실패로는 한 글자 오염을 못 잡는다 |
| keepalive | **쓴다** | 침묵이 곧 오프라인 판정 |
| `seq` | **못 쓴다** | 노드가 안 보낸다. 아래 §seq가 없다는 것 |
| 핸드셰이크 | **안 쓴다** | 왕복 1회가 SF9에서 약 300ms. 19B 하나 보내려고 프레임 3개를 태우고, 그 왕복이 또 유실된다 |
| 슬라이딩 윈도우 | **안 쓴다** | 반이중이라 채널이 하나다. 윈도우를 열 자리가 없다 |
| 혼잡 제어 | **안 쓴다** | TCP는 라우터 큐 포화를 가정한다. 여기 병목은 **매체 충돌**이고 답은 듀티 예산과 지터다 |
| 순서 재조립 | **안 쓴다** | 프레임이 항상 1개다. 분할이 없으면 재조립도 없다 |
| ACK | **안 쓴다** | 노드 N대에 게이트웨이 1대. 전부 ACK하면 게이트웨이가 병목이 된다 |

## 유실은 재전송이 아니라 반복으로 덮는다

프레임 도달률을 90%로 두면:

| 방식 | 미도달 | 지연 | 채널 점유 |
|---|---|---|---|
| 1회 전송 | 10% | — | 222 ms |
| ACK + 재전송 3회 | 0.1% | 최대 3 왕복 (약 1초) | 최대 1초 |
| **10초 간격 3회 반복** | **0.1%** | **왕복 없음** | 666 ms |

같은 신뢰도를 왕복 없이 얻는다. **놓치면 안 되는 것만 반복한다** — ALERT가 선 프레임은
10초마다, 평상시는 어차피 다음 것이 60초 뒤에 온다.

## 왜 base64인가

| 인코딩 | 19바이트 → | SF9 전파 시간 |
|---|---|---|
| CSV (현재) | 76자 | 468 ms |
| hex | 38자 | 264 ms |
| **base64url** | **26자** | **222 ms** |

hex는 2배로 부풀어 바이너리를 고른 이유가 절반 사라진다. base64는 4/3배다.
`-`·`_`를 쓰는 이유는 `+`·`/`가 RYLR AT 파서와 충돌하기 때문이고, 패딩을 떼는 이유는
길이를 프레임 자신이 알기 때문이다.

## seq가 없다는 것

노드가 시퀀스 번호를 보내지 않는다. 그 결과:

| 잃는 것 | 서버 처리 |
|---|---|
| 유실 계측 | 못 한다. `missed_frames`는 항상 0 |
| 중복 검출 | `(device, measured_at, seq)` 유일키가 수신 시각으로만 거른다 |
| 재부팅 감지 | 못 한다 |

**서버가 수신 카운터를 세워 seq인 척하지 않는다.** 지어낸 seq는 "유실 없음"이라는 거짓말을
만들고, 그 거짓말은 통계에 남아 나중에 판단을 망친다. 셀 수 없으면 셀 수 없다고 말한다.

코드에서는 `ABSENT_SEQ = 0` 고정이다.

## 버전 필드를 두지 않는다

포맷이 하나뿐이고 노드가 버전을 보내지 않는다. 구분은 **길이**가 한다 — 19B가 아니면 이
포맷이 아니고, 서버는 `frame_too_short`로 거절한다.

필드를 더하거나 빼면 길이가 바뀐다. 배포 순서는 **서버 먼저** — 새 길이를 이해하게 한 뒤
노드를 올린다.

## 상태 판정을 서버가 한다

노드는 `alert` 비트만 보내고 상태 문자열을 보내지 않는다.

| conditions | 상태 |
|---|---|
| 비어 있음 | `NORMAL` |
| `SENSOR_FAULT`만 | `FAULT` |
| 그 외 | `WATCH` |

FAULT를 NORMAL로 접지 않는다. 포화된 센서는 "정상"이 아니라 "모름"이다.

모르는 ALERT 비트가 서 있어도 **프레임을 버리지 않는다.** `Condition.UNKNOWN`으로 흡수하고
원본 비트를 로그에 남긴다 — 알람이 뜨는 순간이 데이터가 가장 필요한 순간이다.

## 기준선은 오지 않는다

노드는 3분 절사평균 기준선(`baseline_tracker_t`)을 내부에 갖고 있지만 보내지 않는다.
프레임에 실리는 건 현재 레벨뿐이다.

그래서 **"평소의 N배" 같은 상대 표현을 서버·앱이 만들 수 없다.** 지금은 생 레벨을 그대로
기록하고 표시한다.

## 미확정

| 항목 | 상태 |
|---|---|
| `ALARM` 승격 | 규칙 없음. 노드가 WATCH/ALARM을 구분하지 않는다 |
| 기준선 전송 | 안 보낸다. 상대 표현이 필요해지면 노드가 보내거나 서버가 따로 추적해야 한다 |
| 유실 계측 | `seq`가 없어 불가능. 필요해지면 노드에 카운터를 넣어야 한다 |
| 서버 내부 Measure 이름 | `CO_DEV`·`VOC_DEV` 등이 "편차"를 뜻하는데 값은 절대 레벨이다. 이름이 값과 어긋나 있다 |
| 다운링크 | 양쪽 다 없다. 노드에 `+RCV` 파싱이 없어 명령을 받을 수 없다 |
| 노드 주소 배정 | 다중 노드가 되면 필요. 지금은 1 고정 |
