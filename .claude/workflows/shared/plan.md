## When
- 요청을 구현하기 전, 접근·단계·범위·결정·완료기준을 계획으로 잡을 때.

## Inputs
- 요청: 무엇을 하려는지.
- live 컨텍스트: 현재 살아있는 결정·피처 (deprecated·superseded 제외).
- (개정 시) 사용자 피드백.

## Steps
1. 이 작업 영역에 해당하는 규칙을 로드한다.
2. 최초면 컨텍스트·규칙 기반으로 계획 초안을 작성한다. 개정이면 피드백을 반영해 수정한다.
3. 살아있는 결정과 모순되는 부분을 명시한다 (supersede 후보).
4. 계획(접근·단계·범위·내려야 할 결정·완료 기준)을 반환한다.

## Outputs
- 계획: 접근 · 단계 · 범위 · 내려야 할 결정 · 완료 기준(acceptance).
- 코드·테스트 미수정 (produce-only — 계획 텍스트만 반환).

## Handoff
- 코드 구현 → build 절차.
- 충족 판정 → eval 절차.
- 사용자 티키타카 중재·합의 게이트, 계획의 커밋 기록 → 상위(harness).
