## Rule (메타 — 이 컨벤션의 사용법)
- "잘 썼나" 판단하지 않는다. 위반 신호만 검사한다 — 신호 감지 = 즉시 수정, 예외 없음.
- 새 글쓰기 규칙을 만들 때는 추상 원칙("간결하게")이 아니라 셀 수 있는 위반 신호 + 즉시 수정 액션으로 계량화한다. 추상 원칙은 지켜지지 않는다.
- 수치 없는 성과 서술은 지어내지 않는다 — «채우기» 마커를 남기거나 해당 불릿을 강등한다.
- 규칙을 지키다 잘려나간 내용은 삭제하지 않고 부록(면접 확장 포인트·appendix)으로 옮긴다.
- 톤·맞춤법·외래어 표기·존댓말 통일은 `word-writing-writing` 컨벤션을 따른다 — 여기 중복 정의하지 않는다.

## Rule (구조 9 — 불릿·문단 레벨)
| # | 규칙 | 위반 신호 | 즉시 수정 |
|---|---|---|---|
| 1 | 한 문장 = 한 아이디어 | 문장 안 ①② 열거 / 쉼표 4개↑ / 대시(—) 절 2개↑ / 한 호흡에 못 읽음 | 문장 분리, 둘째 아이디어는 부록으로 강등 |
| 2 | 불릿 = 4줄 고정 (헤드라인+문제+행동+결과) | 5번째 줄 / 한 요소 문장 2개↑ / 한 요소 인쇄 3줄(약 90자)↑ | 잘라서 부록행. 헤드라인 오버플로 삭제 순서: 수식어 → 둘째 수치 → 병기 |
| 3 | 헤드라인 = 달성 상태, 도구명 금지 | 헤드라인에 기술 고유명사(Redis·Kafka…) | 도구를 지우고 "무엇이 됐나"로 — 도구는 행동 줄로. 예외 1개: 도구의 비관행적 용법 자체가 성과일 때("git 커밋을 원장 삼아")는 유지 |
| 4 | 모든 줄은 핵심어로 시작 | 줄 첫 7자가 조사·부사·수식어·접속사 | 주제어를 맨 앞으로 |
| 5 | 괄호는 문장당 1개 | 괄호 2개↑ / 괄호 안이 수치·한글 병기가 아닌 설명 | 대시 절로 빼거나 삭제 |
| 6 | 결과 줄엔 숫자 | 숫자 0개 / "안정적·개선·해소" 단독 라벨 | 수치 확보, 못 하면 불릿을 한 줄 (부가)로 강등 |
| 7 | 참조 전 정의 | 위에서 안 깐 개념 등장 카운트 1↑ | 앞 줄·리드에 전제 추가 or 개념 교체 |
| 8 | 용어 3분류 | 표준 용어 풀어씀 / 희귀 용어 병기 없음 / 내부 조어 1개↑ | 각각 압축·첫 등장 한글 병기·삭제 |
| 9 | 지워도 같으면 지운다 | 단어 삭제 후 뜻 동일 | 삭제 확정 |

## Rule (문장 9 — 문장 내부 레벨)
| # | 규칙 | 위반 신호 | 즉시 수정 |
|---|---|---|---|
| 10 | 주어 = 행위자, 동사 = 실동사 | 가짜 동사(진행·수행·실시·도모·제고) / "~가 이루어짐" | "누가 뭘 했나" 물어 실동사로 — "테스트 진행"→"테스트로 검증" |
| 11 | 문장 끝 = payload | 끝 어절이 빈 말(진행·수행·됨·할 수 있음) / 핵심 수치가 중간에 묻힘 | 제일 중요한 명사(수치·메커니즘·결과)를 끝으로 |
| 12 | 구정보 먼저, 신정보 끝 | 문장 첫 어절이 처음 등장한 개념 | 앞 문장이 깐 것으로 열고 새 것으로 닫기. 조사: 화제·구정보 = 은/는, 초점·신정보 = 이/가 |
| 13 | 번역투 blacklist | ~을 통해 / ~에 대한 / ~로 인해 / ~에 있어 / ~를 위해 / '의' 2연쇄 / 및 / ~적 남용 / 문두 그리고·또한 | 치환: ~로·~를 사용해 / 대상 조사 / ~때문에 / 삭제 / ~하려고·관형형 / 하나 삭제 / 와·과·가운뎃점 / 지워도 같으면 삭제 / 삭제 |
| 14 | 내가 한 일은 능동 | 이중피동(되어지다·보여지다) / 주체가 나인데 "~되었다" | "누가?"의 답이 나면 능동. 외부 주체 사건만 피동 허용 |
| 15 | 정도 부사·판단 형용사 = 숫자 or 삭제 | 매우·크게·상당히·대폭·효과적으로·안정적으로 | "대폭 절감"→"79% 절감", 수치 불가면 삭제 |
| 16 | 병렬 통일 | 같은 층위 종결형 불일치(명사형·서술형 혼용) / 나열 구조 불일치 | 층위별 끝맺음·품사 통일 |
| 17 | 주술 호응 | 절에서 "무엇이 어찌했다" 복원 불가 | 주어 복원 or 문장 분리 |
| 18 | 판단엔 근거를 같은 절에 | 기각·채택·전환이 이유 없이 등장 | 이유 관형절을 판단 앞에 — "장애에 똑같이 취약한 sticky session 기각" |

## Rule (어휘 2 — 단어 레벨)
| # | 규칙 | 위반 신호 | 즉시 수정 |
|---|---|---|---|
| 19 | 속뜻 중복(겹말) 금지 | 용어 정의에 포함된 서술이 같은 문장에 또 등장("Pub/Sub으로 전파", 역전 앞·미리 예약) | 속뜻 서술 삭제 — 표준 용어면 삭제, 희귀 용어면 그 서술이 곧 병기라 유지 |
| 20 | 같은 대상 2번째 언급은 압축 | 한 문장 안 같은 명사구 완전형 2회↑ | 관형절 병합("이벤트 전파에 쓴 Pub/Sub은")·생략("담당하던 방")·대체 명사("남은 한 대"). 동의어 교체 금지(one word = one thing). 꼬리물기 반복(앞 절 끝=뒤 절 화제)과 대구("서버와 함께 죽는↔서버 밖")는 정보량 있는 반복이라 허용 |

## Rule (규칙 충돌 시 우선순위)
- 18(근거 인접) > 4(첫 어절 핵심어) — 설득 구조가 스캔보다 우선.
- 19·20 판별식: 반복 자체가 아니라 정보량 0인 반복이 죄.
- 8과 19 교차: 표준 용어는 속뜻 서술 삭제, 희귀 용어는 유지(그게 병기).

## Rule (제출 전 6테스트 — 순서대로, 실패 시 리라이트)
1. 세로 읽기: 헤드라인 + 각 줄 첫 어절만 → 스토리 재구성되면 통과.
2. 끝말 읽기: 각 문장 마지막 어절만 → payload 명사 목록이면 통과, 빈 말 섞이면 실패.
3. 7초 테스트: 헤드라인만 7초 노출 → "뭐 한 사람?"에 한 문장 답.
4. 한 호흡: 소리 내어 읽기 → 숨 2번 = 규칙 1 위반, 입에 걸림 = 13·17 위반.
5. 낯선 독자: 컨텍스트 없는 사람 1명이 문제·한 일·결과 즉답하는가.
6. 숫자 대사: 모든 숫자에 근거 문서 존재 확인.

## Rationale
독자는 7.4초 F-패턴 스캔(Ladders eye-tracking), 페이지 단어의 20~28%만 읽음(NN/g), 문장 25단어↑ 이해도 50%대(American Press Institute), 답 먼저(Minto/BLUF), 독자는 내 컨텍스트를 모름(Pinker curse of knowledge), 주어=행위자·구정보→신정보·끝자리 강조(Williams, Style), 번역투·피동 배격(국립국어원·이오덕), 겹말·정보량 0 반복 금지(Grice 양의 격률·Halliday 결속·Fowler elegant variation). 도구 중심 서술은 "당연해 보임" — 결과 프레임이 차별점(사용자 검증 피드백, 2026-07). 가로폭 확장은 해결책이 아님 — CJK 줄당 40자 초과 시 시선 추적 저하(WCAG).

## Example
```good
서버 1대가 죽어도 게임이 이어지도록 WAS 전체를 무상태로 전환 (접속 50% 단절에도 상태 유실 0)
- 행동: 장애에 똑같이 취약한 sticky session 기각, 상태를 Redis 단일 원본으로 이전 — 대신 생긴 다중 서버 동시 쓰기 충돌은 방 단위 분산 락으로 직렬화
```
```bad
게임 상태를 Redis 단일 원본으로 이전해 해결 (도구가 헤드라인)
- 행동: 다양한 방안을 검토한 뒤 ① Redis 이전을 진행하였고 ② 분산 락(읽기→변경→저장을 직렬화하는 방식)을 통해 안정적으로 개선을 수행 (①② 열거·가짜 동사·번역투·괄호 설명·라벨)
```

## Anti-pattern
- 규칙을 "간결하게 써라"류 추상 원칙으로 남기기 — 위반 신호 없는 규칙은 안 지켜진다
- 근거 없는 숫자 기재 — «채우기» 마커 없이 그럴듯한 수치 채우기
- 압축한답시고 동의어 교체 — 같은 대상은 같은 단어, 압축은 병합·생략으로
