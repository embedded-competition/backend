## Rule
- 함수는 한 가지 일만 한다. 다른 추상화 수준의 코드를 한 함수에 섞지 않는다.
- 함수 줄 수 ≤ 20. 초과 시 추출.
- 함수 인자 수 ≤ 2. 초과 시 인자를 VO/record로 묶거나 메서드 객체로 추출.
- 파일 줄 수 ≤ 200. 초과 시 클래스 분리 또는 같은 폴더 별도 파일.
- 클래스 public 메서드 ≤ 5. 인스턴스 변수 ≤ 3. (객체지향 생활체조 + 이 프로젝트 임계)
- 이름은 의도를 드러낸다. 축약 금지(`mgr`, `svc`, `cnt` X). 도메인 어휘 사용.
- 변수·함수·클래스 이름은 검색 가능해야 한다. 1~2글자 변수 금지 (인덱스 `i` 같은 관용 예외 한정).
- 중복은 추출한다. 단 우연한 일치는 추출하지 않는다 ("세 번째 등장 때 추출" 휴리스틱).
- 비즈니스 로직을 utility static 메서드로 노출 금지. 도메인 객체의 행위로.
- 주석은 기본적으로 적지 않는다. 코드가 자기 자신을 설명하게 한다. 주석은 WHY가 비자명할 때만 (숨겨진 제약·미묘한 invariant·외부 버그 우회).
- 주석으로 코드의 WHAT을 설명하지 않는다. 잘 지어진 식별자가 대신한다.
- 죽은 코드·주석 처리된 코드는 즉시 제거. git history가 SSOT.
- 매직 넘버/문자열은 의미 있는 상수 또는 VO로 추출.
- 선언형 우선(stream/map/filter). 명령형 루프는 부수효과 있을 때 한정.
- 부수효과는 함수 시그니처에 드러낸다. 같은 입력에 같은 출력이 기본.

## Anti-pattern
- 함수 줄 수 > 20 (분리)
- 함수 인자 > 2 (record/VO로 묶음)
- 파일 줄 수 > 200 (분리)
- 클래스 public 메서드 > 5 또는 인스턴스 변수 > 3
- 축약된 이름 (`mgr`, `svc`, `cnt`, `tmp`, `data1`/`data2` 등)
- `// TODO` 누적 (해결하든 issue로 옮기든)
- 주석 처리된 코드 commit
- WHAT을 설명하는 주석 (`// increment counter` 같은 것)
- 의미 없는 매직 넘버/문자열
- utility static 메서드로 비즈니스 규칙 노출
- `Util`/`Helper`/`Manager`/`Processor` 같은 의미 모호 suffix 남발
- 깊은 중첩 (들여쓰기 3단계 초과 — 객체지향 생활체조 1단계 권장)
