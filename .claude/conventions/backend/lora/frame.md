## Rule (프레임은 계약)
- 프레임 포맷은 노드 펌웨어(C)와 서버(Python)가 공유하는 계약이다. 한쪽만 바꾸면 조용히 깨진다.
- 포맷 정의는 `docs/lora-frame.md` 한 곳에 표로 둔다 — 필드명·오프셋·바이트 수·타입·단위·범위.
- 포맷 변경은 첫 바이트 `version` 증가와 함께. 서버는 모르는 버전을 만나면 파싱하지 않고 거절 로그를 남긴다.
- 파서는 `app/infrastructure/lora/frame.py`에만. 다른 곳에서 바이트를 해석하지 않는다.

## Rule (페이로드 크기 — 대역폭이 제약)
- LoRa는 duty cycle 규제와 낮은 실효 속도(SF7/BW125 기준 수 kbps)에 묶인다. 페이로드는 최대한 작게.
- 원시 센서 시계열을 그대로 보내지 않는다. 노드가 상태 판정(NORMAL/WATCH/ALARM/FAULT)을 마치고 결과 + 요약 통계만 올린다.
- 전송 트리거는 두 가지뿐: 상태 전이 발생 시 즉시, 그리고 주기적 heartbeat.
- WATCH 이상에서만 전송 주기를 높인다. 평시에 고빈도 전송하면 duty cycle 예산을 알람 때 못 쓴다.
- JSON 텍스트 페이로드 금지. 고정 오프셋 바이너리(`struct`)를 쓴다.

## Rule (필드 필수 구성)
- `version` — 프레임 포맷 버전 (1바이트).
- `device_id` — 노드 식별자. MAC 하위 바이트 등 고정 길이.
- `seq` — 노드가 증가시키는 시퀀스 번호. 재전송 중복 판별과 유실 감지에 쓴다.
- `measured_at` — 노드 기준 측정 시각(epoch 초 또는 부팅 후 경과 + 동기화 기준).
- `state` — 상태 Enum 값.
- `channels` — 채널별 요약값(현재 편차·기울기 등). 채널 순서는 포맷 문서 순서 고정.
- `crc` — 페이로드 무결성 검사.

## Rule (파싱)
- `struct.unpack`으로 고정 오프셋 파싱. 수동 비트 시프트 산술 금지.
- 엔디안을 명시한다(`<` 리틀엔디안 등). 기본값에 의존하면 플랫폼 차이로 깨진다.
- 파싱 순서: 길이 검사 → CRC 검사 → version 검사 → 필드 언팩 → Enum 변환 → domain 객체 생성.
- 각 실패는 서로 다른 예외로 구분한다(`FrameTooShort`, `FrameCrcError`, `UnsupportedFrameVersion`). 한 예외로 뭉치면 원인 분석이 불가능하다.
- 파서는 순수 함수다 — bytes를 받아 domain 객체를 반환한다. DB·로그·네트워크 접근 금지.
- 파싱 실패 프레임의 원본 바이트를 hex로 로그에 남긴다. 재현이 어려운 무선 경로에서 이게 유일한 증거다.

## Rule (시간)
- 노드 시각을 신뢰하지 않는다. `measured_at`(노드)과 `received_at`(서버)을 둘 다 저장한다.
- 두 시각의 차이가 임계를 넘으면 노드 시계 이상으로 기록한다. 값을 조용히 보정하지 않는다.

## Anti-pattern
- 노드와 서버가 각자 프레임 포맷을 코드에 하드코딩 (문서 SSOT 없음)
- 포맷 변경 시 version 미증가
- JSON·문자열 페이로드 (대역폭 낭비)
- 1Hz 원시 시계열을 LoRa로 전송
- `struct` 대신 수동 시프트·마스크 파싱
- 엔디안 미명시
- CRC 검사 생략
- 파싱 실패를 `except Exception: return None`으로 뭉갬
- 파서가 DB에 저장까지 수행
- 파싱 실패 프레임을 로그 없이 폐기
- `seq` 없이 중복·유실 판별 시도
