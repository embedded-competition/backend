## Rule (현재 인증 상태 — 명시적 부채)
- 앱↔서버 인증은 아직 도입하지 않았다. 이건 결정이지 누락이 아니다 — 근거와 도입 조건을 ADR로 남긴다.
- 현재 방어는 "터널 URL을 모르면 접근 못 한다" 하나뿐이다. 이건 인증이 아니라 은닉이다. 실제 사용자 데이터가 들어가기 전에 반드시 교체한다.
- 도입 트리거: 실제 차량·실사용자 데이터 투입, 공개 시연에서 URL 노출, 쓰기 endpoint 추가.
- 그 전까지 쓰기 endpoint를 최소로 유지한다. 조회는 노출돼도 손해가 작지만 쓰기는 데이터를 오염시킨다.

## Rule (인터넷 노출 경로)
- 터널/DDNS로 외부 노출 시 HTTPS만 허용한다. 평문 HTTP로 노출하지 않는다.
- 내부 진단 endpoint(`/internal/*`)와 문서(`/docs`)는 설정값으로 노출 여부를 제어한다. 기본은 비노출.
- CORS는 앱 origin만 명시. `allow_origins=["*"]`와 `allow_credentials=True` 동시 사용 금지.
- 관리 포트(SSH)를 같은 터널로 노출하지 않는다.

## Rule (비밀값)
- 비밀값은 `.env`와 서비스 계정 키 파일에만. repo에 커밋하지 않는다.
- `.env.example`에 키 이름과 설명만 커밋한다. 값은 비운다.
- 코드에서 접근은 `Settings` 경유. `os.getenv` 산재 금지.
- 비밀 필드는 `SecretStr`. 로그·에러·헬스체크 응답에 노출 금지.
- 키 파일 권한은 `600`, 소유자는 서비스 실행 계정.
- 커밋 전 비밀값 유출 검사를 한다. 이미 푸시된 비밀값은 파일 삭제로 해결되지 않는다 — 키를 폐기·재발급한다.

## Rule (입력 검증)
- HTTP 입력은 Pydantic `strict=True`로 경계에서 검증한다. 검증되지 않은 값이 서비스로 들어가지 않는다.
- LoRa 프레임은 신뢰 경계 밖이다. 길이·CRC·version·Enum 범위를 전부 검사한 뒤 도메인으로 넘긴다.
- 무선 페이로드는 위조·변조가 가능하다. 미등록 `device_id`를 자동 등록하지 않는다.
- 조회 endpoint에 시간 범위와 상한을 강제한다. 무제한 조회는 RPi에서 OOM·DoS 경로다.
- SQL은 항상 파라미터 바인딩. 문자열 포매팅으로 쿼리를 만들지 않는다.

## Rule (에러 노출)
- 클라이언트 응답에 스택트레이스·SQL·파일 경로·라이브러리 버전을 노출하지 않는다.
- 응답은 `{code, message, detail}` 단일 형식 + `request_id`. 상세는 로그에만.
- 미처리 예외는 500 + `request_id`만. 원인 문자열을 그대로 반환하지 않는다.

## Rule (의존성)
- `uv.lock` 커밋 + `uv sync --frozen` 설치. 재현 불가능한 설치 경로를 만들지 않는다.
- 의존성 추가 시 유지보수 상태를 확인한다. LoRa·GPIO 라이브러리는 방치된 것이 많다.
- 취약점 점검을 주기적으로 한다. 발견 시 버전 상향을 커밋으로 남긴다.

## Anti-pattern
- 인증 미도입 상태를 문서화 없이 방치 (ADR 없음)
- 평문 HTTP로 인터넷 노출
- `/docs`·`/internal/*`를 무조건 공개
- `allow_origins=["*"]` + `allow_credentials=True`
- `.env`·서비스 계정 JSON 커밋
- 비밀값을 평문 `str` 필드로 선언
- 유출된 키를 파일 삭제만 하고 재발급 안 함
- LoRa 프레임을 검증 없이 도메인으로 전달
- 미등록 device_id 자동 등록
- 시간 범위·상한 없는 조회 endpoint
- f-string으로 SQL 조립
- 예외 메시지를 그대로 클라이언트에 반환
- lock 없이 의존성 설치
